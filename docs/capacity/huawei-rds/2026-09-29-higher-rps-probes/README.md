# Higher-RPS Huawei probe: 1,200 RPS

Date: 2026-09-29 Asia/Bangkok. The two stages used the same four-API, three-reservation-writer Huawei topology and isolated 800-show synthetic fixture as the [passed 1,000 RPS endurance series](../2026-09-29-audit-batching/README.md). Eight generator workers sent 94% delta seat-map reads and 6% Redis-first holds without retries. The per-show oldest reservation command guard was set to 60 seconds. Source revision: `d378161`.

| Stage | Requests sent | Hold outcomes | Worst-worker read / hold p95 | Post-TTL correctness | Verdict |
| --- | ---: | --- | ---: | --- | --- |
| 1,200 RPS, 5 min | 360,000 / 360,000 | 21,600 HTTP 202; no 503 | 18.75 / 40.21 ms | 21,600 durable; zero overlap; queues empty | All gates passed |
| 1,200 RPS, 15 min | 1,080,000 / 1,080,000 | 64,768 HTTP 202; **32 HTTP 503** | 19.46 / 41.32 ms | 64,768 durable; zero overlap; queues empty | **Failed request/workload gate** |

The 32 hold rejections were `RESERVATION_PERSISTENCE_LAGGING` across all four API workers, not database exceptions, Redis transport failures or general admission-limit rejections. The Redis atomic intake script returns this 503 when the oldest command in that show's persistence stream reaches the configured 60-second maximum age. The rejection prevents accepting a hold whose durable write could miss its lease. All 1,015,200 reads returned HTTP 200. Total-request error fraction was 32/1,080,000 = 0.00296%; hold-request error fraction was 32/64,800 = 0.0494%. These are real failed requests and were not retried or exempted from the strict gate.

The 15-minute writer recorded 64,768 durable commands and no failed persistence outcomes. Its command-age average was 3.86 seconds, p95 in the <=15-second bucket and p99 in the <=30-second bucket; the oldest-entry guard still fired in transient per-show backlogs. The post-TTL audit took 14.36 seconds, scanned all 36,311 historical reservation-stream keys, found no broken links or overlapping seat intervals, and found no pending work. The delta observer recorded no chain anomaly in 1,084 samples. Rollback succeeded. Both stages' synthetic sale fixtures were retired, and the follow-up inventory check found zero active synthetic capacity and zero due reconciliation work.

The passing five-minute probe does not validate 1,200 RPS for sustained use. The current confirmed point remains **1,000 RPS for 30 minutes with 6% holds**, as recorded in the linked endurance series. The limiting behavior at 1,200 RPS is reservation persistence lag on some shows; the available evidence does not isolate PostgreSQL WAL, writer scheduling or stream distribution as its sole cause. A 1,100 RPS sustained stage can narrow the capacity bracket without changing the safety guard.
