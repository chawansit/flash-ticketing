# ADR0187: Bound worker image staging and pre-load gates

## Status
Accepted for local implementation and qualification under ADR0172, ADR0184 and ADR0186. The worker-split experiment is not a registered profile. No cloud staging, deployment or load is enabled by this decision; historical recovery remains unresolved. No accepted decision is superseded.

## Context
The historical staging helper transfers API images to an API-only secondary project. The worker split requires seven background roles and fourteen replicas with exact per-role source and image identities. Partial uploads or lost acknowledgements must retain cleanup ownership without permitting ambiguous image-load replay. A concise pre-load checklist must fail when evidence is missing, stale, mismatched or unsuccessful.

## Decision
Prepare an immutable worker image package locally, using the shared staging-directory generator and existing bounded archive, upload, seal and load helpers. Pin every worker role, deduplicate only identical images with identical source expectations, and bind stable image metadata rather than cache tags or host-specific storage paths. Bind the exact archive digest and size receipt into the fresh scope. Validate the Docker save manifest and config hashes before loading, rejecting extra or duplicate image payloads. Persist source expectations alongside the contract. Require image environment, command and entrypoint defaults to be materialized in the prepared model. Verify source/import/bytecode proofs with isolated, network-disabled image checks; do not start application workers or customers. Give each isolated proof container an exact shared-stage-derived name and ownership labels, reject pre-existing names, and verify identity before removal. A lost proof cleanup outcome blocks staging success.

The staging component has no command-line cloud execution mode. A future registered worker-split profile must supply a fresh ActionGuard binding the prepared pair, staging contract and source expectations. The guard is checked before every forward remote action or transfer. Only sealed, exactly owned archive cleanup can continue after a pause or expired deadline. Durable local intent and receipt files are written before proceeding; failures and unknown outcomes are never replayed. An unsealed partial transfer remains recovery required with its owner intent retained; do not delete an inferred archive or prune Docker images.

Add a local pre-load report to the bounded runner with ten required checklist categories. Each evidence receipt is bound to the exact prepared inputs, has an aware fresh timestamp and all specified checks true. Missing, extra, stale, invalid or failed evidence blocks readiness. Re-check standing pause, unresolved recovery, profile registration and fresh-scope authorization from policy, independently of supplied receipts. A pre-load report is diagnostic evidence, not a deployment or dispatch authorization; actual actions still require registered guarded orchestration.

Local native qualification exposed Docker's OCI archive representation: an immutable image ID may identify an image index instead of a config blob. Support both classic Docker config identities and OCI identities. Require the exact requested OCI root descriptor set, stream-verify every reachable blob's SHA-256 and size, bound graph depth and node count, and require one Linux amd64 runtime manifest per root. Bind Docker compatibility config and layer entries to that runtime manifest. Verify attestation siblings through the same pinned root. Reject unsupported graph types, duplicate roots, invalid platforms and descriptor/content mismatches. See the [OCI image-index specification](https://github.com/opencontainers/image-spec/blob/main/image-index.md) and [descriptor specification](https://github.com/opencontainers/image-spec/blob/main/descriptor.md).

## Alternatives
Reuse API-only staging: misses worker roles and host ownership assumptions. Trust image tags: permits code/image mismatch. Retry partial upload or uncertain load: can overwrite ownership or misclassify completion. Treat an incomplete checklist as warning-only: risks dispatch against an unqualified topology. Register a profile now: premature until live lifecycle and complete correctness/audit integration are qualified.

## Consequences
Image packaging and staging logic can be fault-tested locally before any cloud mutation. The bounded runner can explain blockers in one compact report. Live Kafka dependencies, real worker handover, protected-file restoration, payment throughput and production capacity remain unverified. The preparation report and package do not reset consumed reservations or bypass historical recovery.

## Failure and recovery behavior
Persist owner intent before remote creation. Verify archive content and inode seal before load or deletion. Retain unknown creation/transfer/load outcomes and never replay them. Attempt exact sealed cleanup independently of image proof success; cleanup failure or unsealed remote ownership requires recovery. Preserve all old financial gates and audit expectations. Do not publish image environments, credentials, DSNs, private endpoints or private manifests.

## Validation evidence
Executed: 282 affected tests passed in 19.35 seconds; Ruff passed. Native local Docker packaging and isolated source/import proof passed for seven worker roles across six immutable images, with a 79,484,928-byte verified archive and no remaining proof containers. The initial OCI-format failure is retained with the corrected successful qualification. The real read-only runner report exited blocked for unresolved recovery, unregistered profile, missing fresh scope and missing evidence; it made zero cloud calls. See [sanitized qualification evidence](../capacity/flash-sale-opening/background-service-separation-staging-2026-10-06.json). No live stage, customer load or capacity improvement was measured.
