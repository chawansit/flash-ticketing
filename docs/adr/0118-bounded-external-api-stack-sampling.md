Reuse the existing paid runner unchanged at8refill slots/60buyers per second/300seconds with the same admission/pool/cache/consumer/generator budgets and all financial/queue/source/restoration gates. - **Alternatives:** In-process cProfile/per-request timers change hot request execution; full native/perf sampling has broader overhead/symbol scope; blindly increase threads/connections/cache age/instances can worsen contention or weaken freshness. Deferred until evidence justifies an ADR and separate candidate.
- **Consequences:** GIL-only samples reveal active Python execution, not exact charged CPU, native Rust/C extensions, GIL-released waits or per-request latency. Nonblocking sampling can produce incomplete/inconsistent stacks. Samples in generic framework code may lack route identity; retain an unattributed category rather than guessing. Sampling overhead on the saturated host is a confound: measure profiler CPU and label the replay diagnostic, not an uninstrumented production-capacity comparison.
- **Failure/recovery behavior:** Reject missing/replaced/mismatched targets, unsupported flags, malformed/empty profiles or collector errors. Hard-bound attachment duration and parent deadlines; terminate/reap owned profiler processes on failure. Do not change ptrace/kernel/container security settings. A failed probe remains failed. Stop sampling before configuration restoration; clean only owned transient profiler files/processes after copying raw evidence. Keep exact paid/unpaid postTTL, zero double booking, full-keyspace queue/Kafka/source/readiness/restoredsettings/generatoridle/private cleanup gates. Diagnose collection failure separately from backend correctness; no retries of customer load.
