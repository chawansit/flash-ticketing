## Decision
From the exact verified combined image's22 runtime modules, change only reservations/config/workers. New RESERVATION_LOOKUP_CLAIM defaults off and enables only native reservation writers in an explicit future qualification. Use one SQL statement with a materialized prior-command lookup and conditional INSERT idempotency claim. If the prior command exists, skip the claim and preserve its hash/replay checks. If no command exists, claim the same actor/hold/key/hash with ON CONFLICT DO NOTHING. After a conflicting claim, keep a separate subsequent SELECT for the existing idempotency response; never assume a data-modifying CTE shares visibility of a concurrent committing row. Preserve the exact mismatch/replay metrics and response checks.

Keep seat locks in sorted order with NOWAIT, sale/expiry context after locks, per-command savepoints, batch-four transaction boundary, durable commit before Redis ACK, all writes/outbox/financial semantics, callback behavior and default-off behavior. No application schema/dependency/TTL/retry/correctness change. Four APIs, six consumers/four writers,15workers/3750m/7680Mi, simulator500m,24backends/admission20 remain unchanged.

## Alternatives
Add writer/resources: outside fixed envelope. Repeat rejected batch-eight or outer pipeline: contradicted by retained evidence. Merge seat locking and sale clock: larger locking/timing proof burden. Prefetch all batch replay checks: can miss earlier writes within the same batch. Collapse conflict response read into the claim statement: can miss a row committed after its snapshot. These are rejected.

## Consequences
One fewer round trip for new reservation commands is a hypothesis for higher service capacity and less status polling. SQL still performs the idempotency claim write and command lookup. Existing command replay performs no claim write. Conflicts retain fresh post-wait response visibility. Local median/tail benchmark must demonstrate benefit; no cloud gain is assumed.

## Failure and recovery
Default off preserves old behavior. Domain failures roll back only their savepoint; transient database failures roll back the batch and Redis messages remain unacknowledged. A lost commit acknowledgement replays the same durable command. Reject any source drift beyond three modules. No deploy before integration concurrency/replay/mismatch/savepoint/post-lock TTL and commit-before-ACK tests, actual image verification and a measured local comparison. Any failed cloud quality stops progression, requires actual reconciliation/drain/restoration and fresh identity; original reports remain immutable.
