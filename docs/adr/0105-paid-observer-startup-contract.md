# 0105 - Require live paid observers before dispatch

- **Status:** Accepted on 2026-10-03 before implementation. Repair of the authorized five-minute validation; no additional load stage authorized by this decision.
- **Context:** ADR 0104 requested a 300-second stage plus120-second completion grace, but the pipeline observer rejected its 420-second argument against a 400-second cap. Background launch returned successfully even though the child exited before producing a sample. The load started without pipeline evidence. This is a harness defect, not proof of backend capacity or failure.
- **Decision:** Define a shared bounded observation contract in the pipeline observer module: maximum offered stage 300 s, completion grace 120 s and launch allowance 60 s, maximum observer window 480 s. The runner uses this function and validates both pipeline and Kafka first samples before uploading/starting customer load. Require live observer PIDs, a fresh nonempty sample within a bounded 20-second wait, expected API/consumer counts and no sample errors. Preserve privacy by retaining only a sanitized startup view in public state. Existing raw observer evidence remains private. No backend, retry, persistence, locking, TTL or permanent topology change. This repair does not automatically rerun the failed stage.
- **Alternatives:** Raising only the observer cap leaves silent background startup failures possible. Ignoring missing evidence would invalidate stability conclusions. Increasing load or enabling retries cannot repair observability. Moving measurements into the paid request path changes the system under test and is unnecessary.
- **Consequences:** Future paid stages fail before dispatch if instrumentation is absent or unhealthy. The launch allowance covers bounded setup work but does not prove arbitrary network delays are safe; retain actual observer timestamps and duration coverage in reports. Startup checks add bounded setup time and no customer requests.480 seconds is a ceiling, not an unbounded daemon.
- **Failure/recovery behavior:** Keep observer-started cleanup flags set immediately after successful background launch, before startup verification. A rejected/missing/error sample stops dispatch and still runs observer termination, fixture retirement, original budget/settings restoration and scratch cleanup. Audit the already-running ADR 0104 attempt separately from its missing pipeline metrics; do not declare it passed from Kafka or customer output alone. No next-rate stage, unattended schedule or permanent topology promotion.
- **Validation evidence:** Executed 34 focused tests in 0.95 s, covering 300+120+60=480, rejection above 300/480, CLI 420/480 acceptance, healthy versus missing/error/wrong-replica samples, privacy and existing observer/orchestration regression checks. Changed-file lint and Python compilation passed. Preserve any executed cloud results and exact post-TTL audit. The five-minute attempt at 936224b finished FAILED; its 17,999 paid-ticket post-TTL audit and scoped terminal recovery/drain passed separately. See [failed-stage report](../capacity/flash-sale-opening/paid-five-minute-attempt-2026-10-03.json). Repair is locally verified; no live retest ran. This supersedes ADR 0104's assumption that all existing monitor limits cover its requested duration, while preserving that stage's fixed topology and correctness gates.
