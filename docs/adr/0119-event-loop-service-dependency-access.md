# 0119 - Resolve the service dependency without a thread handoff

- **Status:** Accepted for implementation and same-load evaluation on 2026-10-03; capacity qualification failed in the controlled run; retained on the experimental branch.
- **Context:** ADR0118 captured6954weightedGIL-only stack observations across four API processes for120s. Dependency resolution appeared in18.13percent of sampled stacks; thread handoff/notification in14.09percent (overlapping presence, not CPU fractions). Service(request) is synchronous and returns only request.app.state.reservations, so FastAPI schedules a worker-thread dependency call for this in-memory access. Authentication and actual database/cache operations have distinct synchronous handlers. The external sampling replay remains diagnostic; no exact causal saving is inferred.
- **Decision:** Change only the service dependency to async def, returning the same lifespan-created Reservations object. It performs no I/O, locking or mutation and requires no await inside. FastAPI resolves it on the event loop without worker dispatch. Preserve Actor/JWT checks, handler/webhook database offload, endpoint signatures/output/headers, DB/Redis/Kafka semantics, timeout values, TTL, idempotency, pool/admission/cache/worker budgets and customer retry policy. Supplements the execution placement decision; no ownership/durability/messaging decision is superseded.
- **Alternatives:** Move JWT verification into the event loop too, combine authentication and service retrieval, convert database handlers to asynchronous adapters, or enlarge thread/connection budgets. Deferred: they change additional factors or require separate blocking/security/cancellation evidence.
- **Consequences:** Removes one avoidable dependency dispatch from service-using requests; authentication/handler dispatch remain. No measured CPU/throughput gain claimed before validation. Dependency code must remain an in-memory accessor; future blocking work requires an ADR and appropriate offload.
- **Failure/recovery behavior:** Resolve the same request application state; missing state fails as before and must never create a replacement service or bypass lifecycle. Retain dependency caching and test authentication rejection, actor ownership, private order response and synchronous handler offload through actual FastAPI dispatch. Every exact paid/unpaid postTTL, zero-double-booking, full-keyspace queue/Kafka/source/restoredsettings/readiness/idle/private cleanup gate remains mandatory. Compare against unprofiled61e6c27 control at same8refill/60buyers per second/300seconds; stop profiling before candidate and finish diagnostic recovery before deployment. Failed load prohibits rate escalation/merge/promotion; experimental code may be retained with explicit unqualified evidence.
