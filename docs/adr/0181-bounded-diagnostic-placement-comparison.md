# ADR0181: Bounded diagnostic placement comparison

## Status
Accepted under the standing work envelope; the profile is implemented, locally qualified and cloud-tested. The latest 2+2 control passed and 1+3 candidate failed; no capacity improvement is qualified.

## Context
ADR0180 qualified a separate read-only observer connection. Historical placement profiles use an application account without full statistics visibility and must remain reproducible. A complete runner needs protected staging, exact target/source binding and mandatory credential cleanup before another paid comparison.

## Decision
Add a separate diagnostic placement profile. Preserve ADR0174 runtime markers, frozen application images, connection budgets, workload and financial/customer gates. Compare 2+2 against 1+3 APIs at 60 journeys/second for 300 seconds per arm. Replace only the observer data connection using ADR0180 equally in both arms; preserve its PgBouncer administration connection. Bind a protected, password-free target descriptor into the reservation and verify the mounted trusted CA hash, role/database and exact endpoint. Receive the existing administrator password through protected input only, retain it only in memory, and transmit staging programs over encrypted SSH stdin. Never include credentials in arguments, environment variables, logs, receipts or public manifests.

Use fresh owner-only stage directories generated by the existing runner. Create bundle/CA files exclusively, verify hashes and ownership before opening the diagnostic connection, source-pin transferred helpers, and collect full-visibility preflight before fixture/buyer dispatch. Stop progression on any failed control. Remove exact owned credential/CA files after observers stop, including failures and interruptions; verify absence. Cleanup uncertainty blocks another experiment. Register only after local qualification. Historical profiles and consumed scopes are unchanged.

## Alternatives
Change ADR0174 in place: rejected because old bindings would silently change semantics. Add another concurrent observer connection: rejected because it changes the budget. Grant the application monitoring privileges or discard hidden rows: unnecessary or unproven. Retest the scoped control unchanged: does not address its visibility failure.

## Consequences
The monitoring transport differs from historical runs; only the new matched pair can attribute a placement effect. The administrator role remains privileged even though this session is read-only. Protected staging must therefore fail closed and cleanup is mandatory. This profile does not qualify 84 tickets/second, failover, an hourly sale, or production capacity.

## Failure and recovery behavior
Malformed targets and missing protected context fail before reservation/cloud access. Partial staging records exact owned paths before transfer, so cleanup handles failures after either file is created. No fallback, diagnostic retry, consumed-scope replay or weakened gate is allowed. Application restoration, post-TTL audits and queue drain remain mandatory even when diagnostics fail.
