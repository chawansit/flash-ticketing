# 0116 - Explicit bounded SSH liveness for capacity orchestration

- **Status:** Accepted before implementation on 2026-10-03.
- **Context:** Two paid controls saved completed failed results and exited all generator processes while the local SSH command remained open until480s. In the second run a remote SSH session had no child process while the client still waited. Short SSH completion checks passed. Idle network/session loss is a hypothesis; precise client/server/network cause is unproven.
- **Decision:** Set ServerAliveInterval=15, ServerAliveCountMax=3, ConnectTimeout=10 and ConnectionAttempts=1 on the existing Transport's SSH/SCP options. Retain BatchMode and explicit identity selection, existing command deadlines, checked nonzero exit codes, failed result accounting, redaction and cleanup. No automatic transport retry, generator rerun or customer retry. Compare two silent320second read-only generator-host commands, baseline versus keep-alive; both intentionally exit1 after printing a small result, to verify delivery of failure status without buyer traffic. Keep raw observations private and public summary free of hosts/credentials. This supplements ADR0040's transport liveness; paid-stage recovery orchestration beyond existing capabilities remains future scope.
- **Alternatives:** Increase480s timeout; ignore exit status when a result exists; silently retry load; alter SSH server/TCP settings. Rejected because they prolong waits, weaken gates or change external infrastructure unnecessarily.
- **Consequences:** Small encrypted liveness requests keep otherwise silent sessions active and bound unresponsive peer detection, subject to SSH's operation-specific behavior and parent deadlines. This does not guarantee network availability or prove a firewall idle timeout. SCP accepts the same SSH options. No backend capacity improvement claimed.
- **Failure/recovery behavior:** Unresponsive SSH connections fail; nonzero remote status and parent timeout remain failures. Existing rollback, exact paid/unpaid postTTL, zero double booking, full-keyspace/Kafka/source/restoration/idle/private cleanup checks remain mandatory. Do not infer paid success from transport recovery. The diagnostic has no fixture, payment, API or DB operations; an owned command sleeps then exits, and its client is bounded350s.
