# 0114 - Attribute database pressure during eight-slot requalification

- **Status:** Accepted before implementation on 2026-10-03 under the user-approved conditional roadmap.
- **Context:** Both twelve-slot controls at 60 buyers/s for 300 seconds failed. Nonblocking stream polling reduced durable confirmation p95 but increased customer errors; API pool pressure rose sharply in the final minute. The earlier eight-slot result passed, but current source and fresh fixture history require requalification. The observer omits writer phases, worker DB pools, PgBouncer waits and host CPU, so deeper attribution is unproven.
- **Decision:** Extend the existing bounded paid observer to collect already exported DB timings/pool/process CPU from each worker replica in the same scrape, writer persistence/command-age histograms, aggregate read-only PgBouncer SHOW POOLS/STATS and Linux host CPU tick deltas. Reuse the existing duration/startup/cleanup orchestration. Reject diagnostic startup or final collection errors and counter resets rather than reporting a valid attribution. Keep fixed role/phase labels; no identifiers, SQL payloads, users, DSNs or private host details in public summaries. One additional PgBouncer administrative client consumes no application server slot; application pool24/reserve0/client160 remain unchanged. Requalify eight refill slots at60/s300s, keeping all other backend/generator budgets and 60shows/18000actors unchanged. Application source remains6514dd3; only simulator concurrency changes from12 to8. Added instrumentation and fixture/resource variation are declared comparison limitations. This extends ADR0105's observer contract and supersedes only ADR0112's twelve-slot choice for this diagnostic control.
- **Alternatives:** Increase rate after failed gates; tune DB pools without attribution; query per-order traces; run several independent observers with duplicated scrapes and model polling. Rejected because they confound pressure, expose private data or add unnecessary load.
- **Consequences:** Monitoring adds bounded Redis-free worker scrapes and two PgBouncer administrative reads per sample. Host CPU is machine-wide; process CPU identifies measured API/worker processes but excludes Kafka/PgBouncer and other processes. Sampled gauges can miss short waits. Generic worker operation busy time includes idle discovery and is not pure DB utilization. SHOW STATS is database-wide, not role-specific; exported per-role DB pools/timings provide the complementary view. No production capacity promise.
- **Failure/recovery behavior:** Any missing expected replica, inaccessible admin view, missing CPU data, collection error or counter reset prevents passing diagnostic interpretation and rate escalation. Read-only observations do not change leases, lock order, TTL, idempotency, outbox or delivery semantics. Preserve exact paid/unpaid post-TTL audit, zero double booking, full-keyspace queue/Kafka drain, source identity, baseline restoration, private cleanup and idle generator on success or failure. No90stage under this decision alone.
